### `sphsim/cli/tutorial.py` — new state-machine module, event-driven

**Analog:** No exact codebase analog. Use RESEARCH.md Pattern 1 (TutorialFlow dataclass) directly. The closest structural reference is `sphsim/strategies/__init__.py` for the module-level registration idiom.

**Imports pattern** (`sphsim/strategies/__init__.py` lines 1–10):
```python
from typing import Callable
from sphsim.strategies.naive import strategy_naive
# ...
STRATEGIES = { 'naive': strategy_naive, ... }
BUILTIN_STRATEGIES = frozenset(STRATEGIES.keys())
```

**Core pattern** — TutorialFlow dataclass (from RESEARCH.md §Pattern 1, lines 178–193):
```python
from dataclasses import dataclass, field
from datetime import datetime
from pathlib import Path
from typing import Optional

@dataclass
class TutorialFlow:
    step: int = 1
    total: int = 8
    session_ts: str = field(default_factory=lambda: datetime.now().strftime('%Y%m%d-%H%M%S'))
    hint_count: int = 0
    MAX_HINTS: int = 3

    @property
    def base_report_dir(self) -> Path:
        return Path('reports') / f'tutorial-{self.session_ts}'

    def step_report_dir(self, topic: str) -> Path:
        return self.base_report_dir / f'step-{self.step}-{topic}'
```

**Notable differences:**
- No existing codebase module uses `@dataclass` — this is the first. Use `from dataclasses import dataclass, field` (stdlib 3.7+, confirmed in RESEARCH.md §Standard Stack).
- `TutorialFlow` holds only state data; all display logic lives in `SPHShell` methods (`_show_tutorial_step`, `_check_tutorial_step`, `_show_step_hint`). Keep this separation — mirror how `STRATEGIES` dict is pure data, all dispatch is in `repl.py`.
- The step verification table (8 rows × 4 columns from RESEARCH.md §Step Verification Map) should be defined as a module-level constant in `tutorial.py` so `repl.py` can import just what it needs.

**New additions required in `SPHShell`:**
1. `__init__` — add `self._tutorial_state = None` and `self._last_sim_result = None` (no existing `__init__` in the class; cmd.Cmd uses default — add an explicit `__init__` calling `super().__init__()`).
2. `precmd(self, line)` — new override, intercepts `skip`/`back`/`repeat`/`exit` when `_tutorial_state` is active; returns `''` to short-circuit. Returns `line` unchanged otherwise.
3. `postcmd(self, stop, line)` — new override, checks step completion after each command when `_tutorial_state` is active.
4. `do_tutorial(self, arg)` — new `do_*` method, initializes `TutorialFlow`, prints banner, shows step 1.
5. `_show_tutorial_step`, `_check_tutorial_step`, `_show_step_hint` — private helpers.
6. One line added at end of `do_run`, `do_compare`, `do_batch` (after `res = sim.run()` etc.): `self._last_sim_result = res` / `res_combined` / `{'aggregate': aggregate, 'per_seed': per_seed_results}`.

**Notable differences:**
- `precmd`/`postcmd` are NOT currently overridden in `SPHShell` — these are pure additions.
- Tutorial `exit` in `precmd` must be caught BEFORE `do_exit` fires. RESEARCH.md Pitfall 1 (line 835) confirms `precmd` returning `''` prevents `do_exit` from being called — this is the correct layer.
- `postcmd` must guard `if not line.strip(): return stop` at the top to avoid acting on `precmd` short-circuits (RESEARCH.md Pitfall 2, line 843).
- `_last_sim_result` should be cleared to `None` at the START of `do_run`/`do_compare`/`do_batch` and set only on the success path (RESEARCH.md Pitfall 3, line 849).
- `write_report` calls in `do_run`/`do_compare` must pass `report_dir_override` when `_tutorial_state` is active (D-10). The topic slug lookup uses `_STEP_TOPICS[self._tutorial_state.step]` dict defined in `tutorial.py`.

def _resolve_report_dir(base: Path = None) -> Path:
    """Tworzy ./reports/<ts>/ z collision retry suffiks -N."""
    base = base if base is not None else Path('reports')
    ts = _timestamp()
    candidate = base / ts
    n = 1
    while candidate.exists():
        n += 1
        candidate = base / f'{ts}-{n}'
    candidate.mkdir(parents=True, exist_ok=False)
    return candidate
