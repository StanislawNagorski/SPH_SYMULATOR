Argumenty (verbatim z simulator.py:44-47):
- dev: Device (mutable; ma n_vetoed, veto_phase_stats po Planie 01)
- l: list[int] (l_prev — liczba providerów per faza z poprzedniego cyklu)
- s: int (zajętość bufora SUS)
- phi: list[float] (prawdopodobieństwa fail per faza, 0..1)
- kappa: float (koszt COMMIT)
- rho: list[float] (koszty repair per faza)
- h: callable (i -> i**alpha, hierarchia faz)
- p: dict (parametry strategii, agent czyta tylko gdy expected_P nie podany jawnie do factory)

Zwracana wartość: 'COMMIT' | 'ABSTAIN' | 'VETO' (3-stanowy interfejs z Planu 01 D-65).

Formuła E[zysk_i] (verbatim z incentive.py:12-17):
```
total_h = sum(h(j+1) * l[j] for j in range(len(l)))  # fallback total_h=1.0 gdy <=0
exp_pay = (h(dev.phase) / total_h) * expected_P
net = (1 - phi[idx]) * exp_pay - kappa - phi[idx] * rho[idx]
# Strategia incentive: COMMIT gdy net > 0; ABSTAIN gdy net <= 0
# Agent: passthrough COMMIT gdy net > 0 (lub == 0 — AGENT-02 cytuje literally "< 0" do veto);
#        VETO gdy net < 0
```

Boundary przypadek (D-56 idempotency dla incentive): gdy strategia=incentive zwraca COMMIT przy net>0, agent z identycznym expected_P liczy ten sam net (>0) → no veto. Przy net==0 incentive zwraca ABSTAIN → wrapper passthrough → no veto. Numerycznie idempotent.
